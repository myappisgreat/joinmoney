# 合成錢克禮

使用「照片」資料夾內的 14 張照片製作的合成遊戲。照片依原檔案日期排序，使用 ImageGen 去除背景，轉成帶透明度的 WebP 人物剪影；原始照片保留於專案外的原資料夾。

## 開始遊戲

直接用瀏覽器開啟 `index.html` 即可遊玩，不需要安裝套件或連接外部 CDN。

也可以安裝 Node.js 後執行 `npm start`，開啟 `http://127.0.0.1:4173`。

## 操作與規則

- 電腦：移動滑鼠瞄準，點擊投放；鍵盤左右鍵瞄準、空白鍵投放，P 暫停、R 重開。
- 手機：在棋盤上拖動瞄準，放開投放。
- 兩張相同階級的照片碰撞後變成下一階，共有 14 階。
- 每局小技能：炸彈清場 1 次、換一張 2 次；剩餘次數隨進度存檔，重新整理不會補滿，開始新局才恢復。
- 炸彈：按技能鈕或 B，移動／拖動選擇爆破範圍，再點擊／放開清除範圍內的照片；瞄準時棋盤暫停，重按 B／技能鈕或 Esc 可取消。清除不加分，空炸不扣次數。鍵盤方向鍵可移動爆破位置，空白鍵引爆。
- 換一張：按技能鈕或 X，將準備投放的照片換成另一個初始階級，後續預告照片不受影響。
- 人物以透明去背的不規則輪廓顯示，碰撞範圍取自人物透明度輪廓的凸包，會隨人物一起旋轉。
- 人物改用寬高相近的上半身構圖，長邊統一為 464 像素，保留原比例；平切底邊用向量弧線收尾。
- 遊戲尺寸依第 1 至 14 階逐步放大，基準半徑為 24 至 158。人物互撞反彈係數 0.38，地板接觸單獨降為 0.08；落地只輕微回彈。
- 落地與互撞時會輕微擠壓回彈；系統啟用「減少動態效果」時關閉擠壓動畫。
- 照片穩定堆過警戒線約 2 秒後結束遊戲。
- 結束後保留棋盤、分數和「遊戲結束」畫面，按「重新開始」才開新局；重新整理仍會回到結果畫面。
- 每 2,000 分可獲得一枚復活幣，復活時清除頂部照片。
- 兩個第 14 階互撞會一起消除，加 500 分並獲得一枚復活幣。
- 目前進度、最佳分數、已解鎖圖鑑和前 10 場分數紀錄，儲存在目前瀏覽器的 localStorage。不同裝置與瀏覽器不共用紀錄。

## 檔案

- `index.html`：網頁結構，也是 GitHub Pages 網站入口。
- `styles.css`：電腦與手機版樣式。
- `game.js`：遊戲、物理引擎整合與本機存檔。
- `assets/portrait-01.svg` 至 `portrait-14.svg`：遊戲使用的 14 階人物，內嵌原始去背圖，以向量裁切構圖和弧形底邊。
- `assets/cutout-01.webp` 至 `cutout-14.webp`：保留的原始透明去背素材。
- `assets/photo-01.webp` 至 `photo-14.webp`：保留的原版小圖。
- `assets/shapes.js`：依透明人物輪廓產生的碰撞頂點與圖片重心位移。
- `scripts/prepare-cutouts.py`：將已去背的 PNG 整理為遊戲素材並產生碰撞資料；素材準備階段需要 Pillow，遊戲本身不需要 Python。
- `scripts/prepare-portraits.py`：從去背 WebP 建立人物 SVG 和對應碰撞輪廓；更新去背圖後先跑上一支，再跑此支。
- `docs/cutout-prompts.md`：14 張素材使用的完整 ImageGen 去背提示詞。
- `vendor/matter.min.js`：Matter.js 0.20.0，MIT 授權，授權全文見同資料夾內的 `MATTER-LICENSE.txt`。
- `.nojekyll`：讓 GitHub Pages 直接提供靜態檔案。
- `manifest.webmanifest`、`assets/icons/`：手機主畫面、桌面捷徑與瀏覽器分頁使用的圖示，包含 iPhone 的 180px、Android 的 192px/512px 和可裁切圖示。
- 捷徑使用 `joinmoney.webmanifest`、`joinmoney-v2-*` 專屬圖示與 `?app=joinmoney` 識別，圖像來源固定為這個專案的第 14 階錢克禮照片。`manifest.webmanifest` 保留為相同內容的相容入口。

如果主畫面仍顯示先前快取的其他圖示，請先刪除舊捷徑，重新整理「合成錢克禮」網站後，再從該頁加入主畫面。

遊戲入口已放在儲存庫根目錄，可供 GitHub Pages 使用；開啟 GitHub Pages 服務後，將來源指定為這個分支的根目錄即可。

## 更新與部署

修改遊戲或素材後，執行 `npm run release`，再執行 `npm test`，將所有修改的檔案一起 commit、push。這次已先產生好版本，直接提交即可。

`scripts/prepare-release.cjs` 會依檔案內容產生 JS、CSS、照片與圖示的版本網址，避免新版頁面沿用舊資源；Windows 與 GitHub 的換行差異不影響版本。網頁頁尾會顯示版本，可用來確認發佈結果。此腳本僅需 Node.js，不需安裝套件；GitHub Pages 仍直接使用根目錄靜態檔案，不必切換部署來源。

`npm test` 先檢查資源是否存在、HTML 是否具備遊戲需要的控制項、兩份捷徑設定是否一致，以及資源版本是否最新，再驗證碰撞升級、異階碰撞、連鎖合成、最終階消除、復活清場、落地反彈、技能與結束畫面。

若 Actions 顯示 `updating_pages` 後 `Timeout reached, aborting!`，代表發佈階段超時；資源版本號無法解除伺服器端的部署卡住。請在 Actions 確認最新提交的部署成功，才會看到新版。若重跑任務長時間排隊，可先取消該任務，再選擇 Re-run all jobs；不需要刪除遊戲存檔。

玩法參考：[合成大奶娃](https://yhsome.github.io/BigNaiWa/v1/)。本專案的介面與程式另行實作。
